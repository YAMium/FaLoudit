# FaLoudit — Road Map 0.2

## Цель версии

Версия 0.2 должна превратить готовое диагностическое ядро 0.1 в более полный и стабильный инструмент для ежедневного поиска проблем локализации через CLI и Codex.

Основной пользовательский сценарий:

```text
проблемная строка
 -> автоматический поиск и ранжирование кандидатов
 -> запись и полная цепочка переопределений
 -> победивший плагин и физический файл
 -> мод-источник в MO2
 -> место потери русского текста
 -> готовое диагностическое заключение
```

Проект остаётся диагностическим и полностью read-only по отношению к игре, MO2, профилям, модам и плагинам.

## Статус реализации

- [x] `0.2.1 — Search API`: `edid`, `form`, режимы и фильтры текстового поиска, курсорная пагинация, тесты разрешения идентификаторов.
- [x] `0.2.2 — Analyze API`: единая команда `analyze`, проверка свежести, ранжирование совпадений, полная диагностика записи и явная неоднозначность без догадок.
- [x] `0.2.3 — JSON contract`: additive `schemaVersion: 1`, единая оболочка, контекст профиля и индекса, стабильные коды ошибок, exit codes и тесты совместимости.
- [x] `0.2.4 — Coverage and correctness`: каталог полей, schema 2, `PartiallyParsed`/`Unverified`, команда `coverage`, миграционные и xEdit-oracle тесты.
- [x] `0.2.5 — Reports and performance`: фильтры/пагинация/исключения/пороги, CSV/HTML, сохраняемые диагностические снимки и diff, однопроходная карта MO2 providers, schema 3, история и SQLite health-check, production-упаковка.

## Граница анализа

Версия 0.2 по-прежнему рассматривает тексты, которые представлены в доступных для анализа плагинах и связанных с ними источниках данных.

Строки, создаваемые непосредственно `FalloutNV.exe` или другим исполняемым кодом и отсутствующие в ESM/ESP, не должны ошибочно представляться как пропущенные записи. Например, hardcoded GameSetting `sTo` находится вне цепочки переопределений плагинов.

Возможный каталог runtime- и EXE-строк относится к отдельному будущему направлению и не входит в обязательный объём 0.2.

## Приоритет 1 — полноценный адресный поиск

Добавить команды:

```text
faloudit edid <EditorID>
faloudit form <FormID|FormKey>
faloudit plugin <PluginName>
faloudit mod <ModName>
faloudit conflicts <PluginName>
```

Требования:

- точный и нечувствительный к регистру поиск EditorID;
- разрешение FormID с учётом фактического load order;
- однозначное представление FormKey без зависимости от runtime-префикса;
- сводка плагина: статус разбора, masters, load-order position, физический поставщик и мод MO2;
- сводка мода: активные плагины и относящиеся к диагностике файлы;
- отдельное представление физического конфликта MO2 и конфликта записей плагинов;
- JSON-вывод для каждой команды.

Расширить текстовый поиск фильтрами:

```text
--exact
--contains
--ignore-case
--regex
--plugin <name>
--type <signature>
--category <category>
--winner-only
--limit <number>
--cursor <value>
```

## Приоритет 2 — единая команда анализа

Добавить высокоуровневую команду:

```text
faloudit analyze "<problem text>" --json
```

Команда должна:

1. проверить существование и актуальность индекса;
2. найти и ранжировать кандидатов;
3. отделить точные совпадения от похожих;
4. построить цепочку переопределений для лучших кандидатов;
5. определить победившую запись и физический файл плагина;
6. сопоставить файл с модом и приоритетом MO2;
7. найти более раннее русское значение и более позднюю английскую регрессию;
8. учесть проблемы декодирования и неполного разбора;
9. классифицировать причину либо явно вернуть неоднозначность;
10. сформировать краткое заключение для человека и структурированный результат для Codex.

Команда не должна автоматически выбирать единственную причину при нескольких равноценных кандидатах.

## Приоритет 3 — стабильный JSON API

Ввести версионированный контракт, начиная со `schemaVersion: 1`.

Общий envelope должен содержать:

- версию схемы и приложения;
- режим игры и идентификатор активного профиля;
- исходный запрос;
- состояние и fingerprint индекса;
- данные результата;
- предупреждения;
- типизированную ошибку при неуспехе;
- сведения о пагинации;
- уровень уверенности диагностического вывода.

Нужно документировать:

- обязательные и необязательные поля;
- значения enum;
- правила совместимости схем;
- exit codes;
- поведение при устаревшем и частично построенном индексе.

`physicalFileWinner` и `recordWinner` должны быть представлены раздельно во всех подходящих ответах.

## Приоритет 4 — качество и полнота извлечения строк

Провести систематический аудит record types и пользовательских текстовых полей Fallout 3, Fallout: New Vegas и TTW.

Добавить:

- каталог поддерживаемых типов записей и полей;
- статистику покрытия по типам и полям;
- статус `PartiallyParsed` наряду с `Parsed` и `Failed`;
- предупреждения о пропущенных вложенных или неизвестных полях;
- fixtures с кириллицей и сложными специальными случаями;
- сверку выбранных цепочек переопределений с FNVEdit/FO3Edit как correctness oracle;
- команду или режим `coverage`, формирующий машиночитаемый и человекочитаемый отчёт.

Неподдерживаемое поле должно быть видимой диагностической информацией, а не тихим пропуском.

## Приоритет 5 — ранжирование и масштабирование поиска

Исследовать и при необходимости внедрить SQLite FTS5.

Порядок результатов должен учитывать:

- полное точное совпадение;
- точное совпадение нормализованного текста;
- совпадение всей фразы;
- частичное совпадение;
- принадлежность победившей записи;
- наличие RU -> EN регрессии;
- соответствие заданным плагину, типу и категории.

Для коротких запросов должны применяться защита от чрезмерного количества слабых совпадений и обязательная пагинация. Результаты с одинаковой оценкой должны иметь детерминированный порядок.

## Приоритет 6 — массовые отчёты

Улучшить команды `regressions`, `untranslated` и `report`:

- фильтры по типу записи, плагину, моду и категории поля;
- постраничная обработка;
- устранение диагностических дублей;
- настраиваемые пороги уверенности;
- список исключений для намеренно английских строк;
- JSON, CSV и HTML-представления там, где это практически полезно;
- сравнение двух снимков индекса;
- отчёт о новых проблемах после изменения сборки.

## Приоритет 7 — необязательный поиск в отключённом контенте

Спроектировать отдельный вторичный каталог переводов из отключённых модов и плагинов.

Он может отвечать:

> В активной цепочке победил английский текст, но русский вариант найден в отключённом моде X.

Отключённый контент не должен участвовать в определении активного победителя. Результаты такого поиска должны быть явно помечены как справочные.

## Приоритет 8 — производительность и эксплуатация

Улучшить обслуживание большого MO2-профиля:

- кэшировать карту физических поставщиков без ослабления проверки актуальности;
- ускорить определение изменившихся модов и плагинов;
- сохранять краткую историю обновлений индекса;
- показывать возраст, размер, backend version и состояние SQLite;
- диагностировать повреждение кэша;
- обеспечить безопасное прерывание и повторный запуск;
- документировать обслуживание базы и критерии полного перестроения.

## Не входит в обязательный объём 0.2

- Fallout 4;
- изменение ESM/ESP;
- автоматический перевод;
- создание патчей;
- редактирование профиля MO2 и load order;
- очистка мастеров;
- замена xTranslator;
- собственный бинарный парсер плагинов;
- полноценный GUI;
- BSA repacking;
- универсальная база hardcoded-строк из EXE.

Чтение external STRINGS или BSA следует добавлять только после подтверждённого проблемного случая в поддерживаемой FO3/FNV/TTW-сборке.

## Критерии готовности 0.2.0

Версия 0.2.0 считается готовой, когда:

- пользователь может искать по тексту, EditorID и FormID/FormKey;
- `analyze` выдаёт полную диагностическую цепочку одним вызовом;
- физический победитель MO2 никогда не смешивается с победителем записи;
- JSON имеет документированную стабильную схему;
- большие наборы результатов поддерживают пагинацию;
- неподдержанные или частично разобранные данные явно видимы;
- ключевые случаи подтверждены автоматическими тестами и выборочной сверкой с xEdit;
- все операции с пользовательской сборкой остаются read-only;
- Windows x64 package и Codex project package собираются воспроизводимо;
- README и инструкция Codex соответствуют фактическому CLI.
